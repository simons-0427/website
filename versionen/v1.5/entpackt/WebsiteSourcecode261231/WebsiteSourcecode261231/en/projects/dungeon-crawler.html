Dungeon Crawler

A dungeon game written entirely in C with raylib. The player navigates a map, avoids enemies and collects items.

🎮 Game development v1.6 18 October 2026

Dungeon Crawler v1.6

About the project

What is Dungeon Crawler?

Dungeon Crawler was my first larger C project. The goal was to build a fully playable game with standard C.

The map is built from a two-dimensional array. Walls, open tiles, enemies and items each have their own symbols. The player moves with the arrow keys, avoids enemies and collects treasure.

Built with: C | compiled with GCC | runs as a standalone windowed application

Features

What can the game do?

  • Graphics: The game runs in a 1280×720 raylib window; the map, player, enemies and effects are rendered with GPU acceleration.
  • Player movement: WASD or arrow-key controls with collision detection for walls, traps and other objects.
  • Enemy AI: Enemies actively pursue the player with X/Y pathfinding; contact kills the player. Enemies can be toggled on and off.
  • Round-based progression: Each round uses a procedurally generated map. Treasure ends the round, while a portal skips to the next one.
  • Coins and traps: Coins increase the score. Traps kill the player immediately unless a shield is active.
  • Particles and camera: Explosions, coin sparks and death effects use a particle system; the camera follows the player smoothly.
  • High score and persistence: Best round, most treasure, most coins and lifetime coins are saved to a file and shown in the menu.
  • Game over and restart: After dying, the game can be restarted or the main menu can be opened.
  • Item system: Up to three of six upgradeable item types can be carried and used with keys 1–5. Each item can be upgraded in the shop.
  • Achievements: A dedicated menu shows 21 achievements, including rounds played, coins collected and kills. Each has six progress levels.
  • 43 skins across five rarity levels: Common, Uncommon, Rare, Epic and Legendary skins are available through the shop and progression.
  • Music system: Background music and sound effects are integrated through raylib AudioStream.
  • Settings: Audio levels, enemy toggles, fullscreen and visual settings can be changed.
  • Boss fights: A fire-breathing boss summons enemies and must be defeated every ten levels.
  • Alternative levels: Lava floors, trap rooms without enemies, coin rooms and dark rooms create different challenges.

Technical details

How it was built

The project still consists of a single .c file, now grown to roughly 5,350 lines of code. It uses raylib, a C library for 2D and 3D graphics. The map is a static 2D array of char values (char map[MAP_ROWS][MAP_COLS]) that is generated procedurally at runtime rather than hard-coded.

/* Karte wird zur Runtime generiert */
for (int y = 0; y < mh; y++)
for (int x = 0; x < mw; x++) {
    int r = GetRandomValue(0,99);
    map[y][x] = (r < tp) ? '#' : (r < xp) ? '+' : '.';
}

/* Tile-Map-Konstanten */
'#' = wall,  '.' = floor,  '+' = trap
'T' = treasure,  'O' = portal,  '$' = coin
'I' = item,  'X' = enemy

Rendering with raylib: Each tile is rendered at 32×32 pixels. Walls receive 3D bevel effects, while items and enemies are animated shapes and circles. The camera follows the player smoothly and particles update every frame.

Input with raylib: Keyboard input uses IsKeyPressed() and IsKeyDown(). It works across platforms without special handling.

Game logic: A state machine (`GState`: MENU → PLAY → DEAD/NEXT) controls the flow. The main loop uses delta time (`GetFrameTime()`) for consistent physics at 60 FPS. Enemy AI, particles, timers and camera movement are updated independently of the frame rate with `dt`.

Persistence: High scores such as the best round, treasure and coins are written to and loaded from a file (`STATS_FILE`).

Shop and progression: Each of the five items has its own upgrade level, read from an array with duration and range per level. Skin ownership, levels and coins are stored separately (`SHOP_FILE`). The skins are grouped by rarity and rendered with dedicated drawing functions. Achievements use the same stats and are checked live against each level's target.

Reflection

What I learned

I implemented the game logic with C, pointers and arrays. With raylib, I built a graphical interface.

Later, I added a web build with Emscripten, which lets the game run in the browser. WebAssembly and different build targets required additional adjustments.

The project deepened my C knowledge and taught me how to structure code as new mechanics are added. I also gained a clearer understanding of how game logic, rendering and user input work together.
